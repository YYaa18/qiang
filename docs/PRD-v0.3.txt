1. 背景与问题
四个朋友想在同一张纸上同时涂鸦、写字、聊天。现成工具能用，但会把别人的交互习惯带进来，也没有一间真正属于这四个人、关掉明天还在的房间。本项目自研最小可用版本，先让四人当晚能用起来。
1.1 要解决的问题
	•	没有一处固定的共同画面：微信发图是单向的，视频通话共享屏幕只有一个光标。
	•	画和话是分开的：画在一个地方，字在另一个地方，事后对不上。
	•	房间容易一次性用完：白板用完即弃，没有「我们这面墙」。
1.2 为什么现在做
	•	人数固定、场景清楚，不需要社区、账号、匹配。
	•	电脑端四人同步，技术复杂度可控，一个人两周内可交付。
	•	先验证「会不会反复打开同一面墙」，再决定要不要加功能。
2. 产品定义
2.1 定位
墙是朋友之间的常驻涂鸦墙，不是你画我猜，不是专业画板，不是公开像素大战。它更接近宿舍里钉着的一张卡纸：有边界、有在场的人、允许互相覆盖、清空需要仪式。
2.2 产品原则（不可妥协）
	•	30 秒能落下第一笔。不要注册。
	•	画和聊平权。只画不打字也算在说话。
	•	同一链接就是同一面墙。刷新、重开、明天回来，画还在。
	•	颜色即署名。身份色（光标、名字、座位）四色认人；画笔颜色任选。
	•	撤销只撤自己的。清空是全员可见的仪式。
	•	墙是一条横向卷轴。默认一段，可以一直向右接长；不做上下左右的无限画布。
2.3 目标与非目标
本版本要做
本版本明确不做
	•	创建 / 加入房间（短码 + 链接）
	•	横向卷轴涂鸦与墙上文字（可一直接长）
	•	实时光标与在场名单
	•	侧边聊天
	•	自己的撤销 / 重做
	•	房主：锁定、清空倒计时、踢人、导出 PNG
	•	断线重连与刷新不丢画
	•	账号 / 邮箱 / 第三方登录
	•	公开大厅与陌生人匹配
	•	语音 / 视频（继续用现有通话）
	•	图层、笔压、自定义笔刷
	•	上下左右的无限画布、多页画布
	•	游戏模式、积分、排行
	•	完整移动端适配、回放时间轴
非目标不是永远不做，是第一版不做。有人连续两周使用同一房间后再开第二期。

4. 用户流程
4.1 创建墙
	•	打开网站，看到门口页。
	•	点「砌一面墙」。服务端生成 4 位大写房间码（排除易混字符 I、O、0、1）。
	•	创建者填写昵称（若本地已有则预填）。成为房主，分到朱红。
	•	进入墙。顶栏可复制链接 https://{host}/w/{CODE}。
4.2 加入墙
	•	打开链接，或在门口输入房间码点「推门」。
	•	若房间不存在：提示「没有这面墙」。
	•	若已满 4 个在线席位：提示「墙满了」，不可进入。
	•	填写昵称，分到下一个空闲颜色，进入。
	•	全员收到系统句：「某某来了」。
4.3 在墙上
	•	默认工具为笔，粗细为中，颜色为本人主色。
	•	在纸上拖动画线；点「字」再点纸面落下文本框，回车确定。
	•	右侧聊天回车发送。
	•	离开或关页：10 秒内未重连才广播系统句「某某走了」并释放席位；10 秒内回来不提示、不重新分色。画保留。
4.4 再来
同一浏览器记住 clientId 与昵称。同一链接进入同一面墙。原色空闲就还原色，否则分下一个空闲色。房主身份绑定 clientId，与昵称无关。

5.1 门口页

验收标准
创建
一键生成房间并进入，无需注册。

文案

错误

5.2 房间
项
验收标准
房间码
4 位大写，字符集 ABCDEFGHJKLMNPQRSTUVWXYZ23456789。
容量
同时在线 ≤ 4。第 5 人被拒。离线后席位可被新人占用。
重复连接
同一 clientId 的新连接顶替旧连接，旧标签页提示「已在别处打开」。刷新和双开都不重复占席位。
持久化

有效期

复制链接
一键复制，复制成功有轻提示。
5.3 画布
项
验收标准
尺寸
横向卷轴：每段 1600×1000 画布像素，默认 1 段。纸纹理全墙共用一张图，笔画画在其上的透明层。进墙时纸的高度铺满屏幕，从最左端开始。
接长
卷轴末端有「接一段」，点一下全员的墙向右接出一段，系统句「某某把墙接长了一段」。任何人可接；锁定时只有房主能接。上限 500 段，仅防滥用。
工具
笔、橡皮、文字。不可同时激活两个工具。
粗细
笔：细 3 / 中 8 / 粗 18。橡皮：细 8 / 中 18 / 粗 36（画布像素）。
颜色
任选。快捷色：本人主色 + 黑白灰 + 最近的自定义色；调色板：24 色预设、最近用过、取色器、十六进制。拿着橡皮选颜色会自动切回笔。
白色
白色是画笔色，效果是「涂白」，与橡皮是两回事。
笔
按下移动抬起为一条 stroke。点列按移动采样，直线连接。
橡皮
在笔画层上真擦，露出下面的纸纹，不用白色覆盖。可以擦到任何人的笔。一次擦除算自己的一笔，可撤销。
文字
单击落框，Esc 取消，Enter 确定。字号 22。颜色用当前选色。算一笔。
缩放平移
普通滚轮沿卷轴横向移动；Ctrl/⌘+滚轮或触控板捏合缩放（最多缩到约 3 段可见，最大 200%）。空格拖或中键拖平移。「回正」恢复高度铺满。
越界
笔画点可超出纸边 40 画布像素，超出部分由画布自然裁掉，不会贴边画线。坐标保留 1 位小数。
卷轴导航
底栏显示「第 n / N 段」，小条每段一格，用本人主色框出当前可见范围，点击跳转。
清晰度
墨迹画布按 devicePixelRatio 创建。只为屏幕附近 3～4 段建画布，滚走的段释放，墙多长都不会撑爆浏览器内存。
工具提示
工具条每个按钮悬停约 0.35 秒弹出提示：名称、快捷键（按系统显示 ⌘/Ctrl）、一句用法。禁用的撤销/重做也会说明原因。
未完成的笔
画到一半断线，或画到一半被锁定时，服务端代为结束这一笔并落盘。
5.4 同步与光标
项
验收标准
他人落笔
同城体感延迟 < 150ms。绘制过程中可见正在延伸的线，不只完成后闪现。
光标
他人光标为对应颜色小点 + 昵称。超过 3 秒未移动则降低存在感（半透明），移动即恢复。
新进房
先拉全量已完成笔画，再接收增量。不出现「先看到新笔、后看到旧画」。
叠放顺序
服务端收到 stroke_start 时分配递增 seq，墙面按 seq 从小到大绘制。正在画的笔可临时显示在最上层，结束后回到自己的层级。
断线
底栏显示「重连中」。重连成功后重新拉取全量 snapshot，在离屏画布上画好后一次替换，不闪白。不做增量补发协议。
5.5 在场与聊天
项
验收标准
名单
顶栏正中 4 个座位：色点 + 名字 + 「我 / 房主 / 离开中」；空位用虚线格。房主悬停别人的座位可「请离」。
聊天宽度
右侧约 280px，默认展开。可收起成竖栏，收起期间显示未读数，展开后清零。
发送
Enter 发送，Shift+Enter 换行；输入法选词时的回车不发送。空消息不发。单条 ≤ 200 字，≥ 150 字时显示字数。输入框随内容长高。
历史
最近 100 条常驻。更早的 MVP 可丢。
系统句
来了 / 走了 / 锁定 / 解锁 / 清空 / 被踢 / 接长。连续的系统句合成一行，小字居中。
消息分组
同一人 3 分钟内连续的消息合成一组，左侧竖线为其主色，自己的消息带浅底。间隔 5 分钟插时间分隔。往上翻看时来新消息不强行滚动，显示「有新消息 ↓」。
进出提示
顶栏座位下方弹出精简胶囊「某某 来了 / 走了 / 被请离了」，2.5 秒淡出，最多叠 3 条；新座位闪一下。离开在 10 秒宽限期后才提示，刷新不误报。
5.6 撤销
项
验收标准
范围
只能撤销 / 重做自己的 stroke（含橡皮和文字）。按 clientId 判定，刷新后仍能撤销刷新前的笔。
实现
撤销是把该 stroke 标记为隐藏，不删除。重做是取消隐藏，笔回到原来的层级。
栈
每人最多 50 步，永久保留（离开再回来也能撤）。画新的一笔后，自己的重做栈清空。撤销一笔已冻结的旧笔时，服务端从矢量存档把所在段整段重画。
快捷键
Ctrl/Cmd+Z 撤销；Ctrl/Cmd+Shift+Z 或 Ctrl+Y 重做。
同步
撤销后他人墙上对应笔消失。不提供「撤别人」。
清空后
全员的撤销栈和重做栈都清零。
锁定时
非房主不能撤销或重做。
5.7 房主工具
项
验收标准
锁定
锁定后非房主不能画、不能在墙上写字，仍可聊天、仍可见光标。顶栏显示「已锁」。
清空
点清空 → 全员看到 5 秒倒计时遮罩 → 房主可取消 → 到期后 strokes 清空，聊天保留，系统句「墙被清空了」。
清空中断线
倒计时由服务端计时。房主在倒计时期间断开，到期照常执行。
踢人
房主点名单旁「请离」。被踢者回到门口并提示。席位释放。
房主离线
房主断开后房间仍在，MVP 不转移房主。同一 clientId 重连即收回房主权。
导出
任何人可导出整条卷轴为一张 PNG，含纸纹，不含 UI 和光标。超过 32000 像素宽（20 段）时按比例缩小。文件名 墙-{CODE}-{时间}.png。

6. 信息架构与界面
6.1 页面地图
/  门口：创建或加入。
/w/:code  墙：唯一主界面。设置全部收在顶栏「⋯」。
无其他页面。无个人主页、无大厅、无设置中心。
6.2 门口结构
	•	产品名「墙」与四色点，不放宣传语。
	•	主按钮：砌一面墙。
	•	次操作：房间码输入 + 推门。
	•	无页脚营销、无登录入口。
6.3 墙的布局
桌面三区，画布是唯一视觉中心。
顶栏
左：房间码、复制链接。中：四个座位。右：锁定状态、⋯（导出 / 改名字 / 锁定 / 清空）。
左工具条（窄）
笔、橡皮、字、粗细三档、四色、撤销、重做、回正。竖排。图标 + 悬浮中文名。
中：桌面 + 纸
浅灰桌面。中央 1600×1000 的纸。纸外不可画。
右：聊天
名单（可与顶栏二选一，实现时顶栏人数 + 聊天顶四色点即可）+ 消息流 + 输入框。
底栏
连接状态；谁正在画（有人按下鼠标时显示「某某落笔中」）；卷轴导航（第 n / N 段，点击跳转）。
线框说明。视觉关键词：纸、铅笔、宿舍灯。不要做成 SaaS 白板，不要做成游戏大厅。
6.4 视觉约束
	•	背景偏暖灰，纸偏暖白，不要纯 #FFFFFF 铺满全屏。
	•	工具选中态用本人主色描边，而不是蓝色系统色。
	•	聊天昵称用该人主色，正文用墨色。
	•	无圆角大按钮堆砌，无渐变，无拟物游戏框。
	•	中文字体优先系统黑体 / 雅黑；数字与房间码用等宽。
7. 交互原则
	•	先有人，再有笔。进房先看到谁在，再看到工具。四个人是产品，纸是媒介。
	•	笔迹即发言。允许只画不打字。
	•	覆盖是允许的，清空是仪式。第一版不做保护区。
	•	撤销是个人礼貌，不是全局时光机。
	•	墙是卷轴。先在一段里挤着画、互相遇见，画满了再一起接长。
	•	颜色即署名。
	•	沉默也是在场。光标停着，名单仍显示。挂机是合法用法。
8. 数据与接口
8.1 房间对象
room = { code, createdAt, hostId, locked, users[], strokes[]（仅最近的矢量笔）, chat[], segments, frozenUpTo, segVersions{段号: 版本}, clearDeadline? }
8.2 用户
user = { id, name, color, lastSeen }。id 即 clientId，由客户端首次打开时生成并保存在本地，服务端只校验格式。昵称仅作显示，不保证全局唯一。
8.3 笔画
stroke = { id, seq, userId, type: 'pen'|'eraser'|'text', color, width, points?: [{x,y}], text?: string, x?: number, y?: number, hidden, t }。seq 由服务端分配，决定叠放顺序；hidden 标记撤销状态。
坐标原点为卷轴最左一段的左上角，单位为画布像素。服务端把点裁切到 [−40, 段数×1600+40]×[−40, 1040]，并保留 1 位小数。
8.4 聊天
message = { id, userId|'system', text, t }
8.5 实时事件（WebSocket）
事件
方向与含义
join
C→S 房间码 + 昵称 + clientId。S 回 snapshot 或 error。同一 clientId 已在线时，断开旧连接。
snapshot
S→C users、最近的矢量 strokes、chat、locked、segments、frozenUpTo、segVersions、你的 id 与角色。
stroke_start
C→S 开始一笔（id、type、color、width、首点）。S 广播。
stroke_point
C→S 增量点。可打包。S 广播。
stroke_end
C→S 结束一笔。S 落盘并广播。
text_place
C→S 文字笔。S 落盘并广播。
undo / redo
C→S 自己的一步。S 广播移除或恢复该 stroke id。
cursor
C→S 节流 50ms 的 x,y。S 转发给房内他人。不落盘。
chat
C→S 文本。S 落盘并广播。
lock / unlock
房主 C→S。S 广播。
clear_start / cancel / done
房主发起 5 秒倒计时。到期 S 清空 strokes 并广播。
kick
房主 C→S targetId。S 断开对方并广播名单。
presence
S→C 有人进出。
extend
C→S 接长一段。S 广播新的段数。
bake
S→C 请一个在线客户端烘焙某段：增量（在旧墨迹图上叠新冻结的笔）或整段（从存档重画）。客户端画好后 POST /api/rooms/{CODE}/seg/{n}?job= 上传 PNG。
baked
S→C 某几段的墨迹图有了新版本、冻结线推进到 upTo。客户端 GET /api/rooms/{CODE}/seg/{n}.png?v= 取图（可长缓存）。
8.6 持久化
	•	每面墙一个元数据 JSON：最近的矢量笔、聊天、撤销栈、段数、冻结进度。只在有改动时写盘，最多每秒一次。
	•	服务重启时加载 data/rooms/{CODE}.json。
	•	不引入数据库，除非已经有现成的且不会拖慢交付。
	•	服务端是唯一真相。客户端本地缓存仅用于自己未发送完的一笔。
	•	写盘时先写临时文件再 rename，避免进程被杀时 JSON 损坏。多次写盘请求合并，最多每秒写一次。
	•	旧笔冻结：保留最新 150 笔为矢量；多出 200 笔时，由在线客户端用同一套绘制代码把更早的笔烘焙进每段一张 2 倍分辨率的墨迹图（透明 PNG）并上传。冻结的是一整段 seq 前缀，叠放顺序不变。
	•	矢量存档 archive.jsonl 永久保留在磁盘，只在撤销 / 重做已冻结的笔时读取，用于整段重画。烘焙者掉线或 30 秒超时，本批作废并换人重来。
	•	WebSocket 对 8KB 以上的消息（进墙快照）启用压缩。
9. 非功能需求
9.1 性能
	•	4 人同时连续画，目标端到端 < 150ms（同城）。
	•	笔数和长度不设上限：旧笔冻结后，元数据和进墙下载量保持很小；浏览器只为屏幕附近 3～4 段建画布。
	•	实测 4 人连续绘制：服务端约 114 条/秒进、380 条/秒出，CPU 约 6%（M 系列 Mac），内存 < 80MB。1 核 512MB 的 VPS 足够。
	•	光标消息必须节流，不得按鼠标采样频率原样广播。
9.2 可靠
	•	单人刷新不丢画。
	•	服务进程被杀后，已 end 的笔画从磁盘恢复。
	•	WebSocket 断开自动重连，最多提示，不要求用户手动刷新（刷新作为兜底）。
9.3 安全与隐私（朋友局最小集）
	•	无公开列表，知道链接才能进。
	•	不做内容审核后台。四人认识。
	•	房间码空间约 32^4，对朋友局足够；不防扫描。需要时可加密码（不在 MVP）。
	•	不收集邮箱、手机、精确位置。昵称存在房间 JSON 里。
	•	clientId 相当于本人的钥匙，只存在本地。知道别人的 clientId 就能冒充他，朋友局接受这一点。
9.4 兼容
	•	第一目标：桌面 Chrome 近两个大版本。
	•	应能在 Edge、桌面 Safari、Firefox 打开并画。
	•	不保证手机体验。不阻止打开，但布局按 1280×720 以上设计。
9.5 无障碍（最低）
	•	工具按钮有 aria-label 和悬停提示（名称 + 快捷键 + 用法）。
	•	聊天输入可用键盘。
	•	不把信息只放在颜色上：名单同时有昵称。
10. 技术建议（不绑定实现，供开工）
	•	前端：一份静态页即可。Canvas 2D 绘纸。不必上框架；若习惯可用任意轻框架。
	•	传输：WebSocket。JSON 足够。点列密集时可对 stroke_point 做二进制，但第一周不要做。
	•	后端：Node（ws 或 socket.io 择一）单进程。四人一房，一台最小 VPS 或本机穿透即可试玩。
	•	坐标与缩放：内部永远用画布坐标，屏幕坐标只在事件入口换算。
	•	绘制：本地正在画的一笔即时画；他人的笔按事件画。全量重绘只在撤销、重做、清空、进房、重连时发生。
	•	部署：本机 + cloudflared 临时隧道，或 VPS（systemd + Caddy 自动 HTTPS + 每日备份），见代码仓库 deploy/README.md。
不在第一版使用 CRDT。冲突模型：后到的点盖住先到的点，和真纸一样。
11. 成功标准与测试
11.1 两周产品成功（任意两条即过）
	•	同一房间链接被打开 ≥ 5 次。
	•	墙上同时存在画和字，且互相有回应，不是四人各占一角。
	•	有人把导出图发到群里。
	•	出现「别盖我的」——说明他们在乎这面墙。
11.2 失败信号
	•	第一次就要注册或装东西。
	•	第二次打开房间空了。
	•	朋友说还是发微信图片更快。
11.3 当晚验收脚本（四人）
	•	房主砌墙，三人用链接进来。确认四色不同。
	•	每人在自己一侧画一个东西。确认互相看得见过程，不只看见结果。
	•	每人在别人的画旁边写一句话。
	•	四人一起在纸中央画「今晚的东西」。
	•	一人撤销自己最后一笔，他人墙上同步消失。
	•	房主点清空，全员看到倒计时，取消一次，再真正清空。
	•	一人刷新，画还在。一人断网 10 秒再连，能补上断线期间别人的笔。
	•	导出一张 PNG。第五人尝试进入，被拒。
	•	结束后只问一句：明天还想打开这面墙吗？

14. 第二期候选（未批准，禁止提前做）
	•	房间口令。
	•	多页：今晚一页，下周新开一页，旧页只读归档。
	•	回放：按时间重放笔触。
	•	悬停一笔看出作者与大致时间（画笔颜色放开后更有必要）。
	•	导入一张参考图当纸底。
	•	房主转移。
	•	每日自动快照缩略图。
	•	身份链接：生成一条带本人 clientId 的私人链接，在新设备打开即恢复身份。这是跨设备方案，不做账号。
开第二期的前提：同一房间被四人反复使用，而不是功能清单还有空行。
15. 开放问题（开发中可自行拍板）
	•	房间码 4 位是否改为 5 位：4 位对朋友局够用，保持 4 位。
	•	离线用户是否占席：不占。在线满 4 才拒。
	•	文字是否允许换行：MVP 单行，超长截断到纸边。
	•	导出是否含水印：不带。
	•	正式产品名：上线前再定。代码与域名可用 qiang 或 wall。
	•	要不要做登录：不做。本地 clientId 已满足撤销、房主和还色的需要。
	•	颜色漂移：接受。旧笔保留当时的颜色，不跟着人走。
	•	被踢后能否立刻重进：可以。踢人是提醒，不是封禁；需要封禁时再加口令（二期）。
	•	要不要回放：不做。
	•	撤销保留多久：一直保留。
	•	画笔颜色：任选；身份色仍按进房顺序四色分配。
	•	要不要拆出独立服务端：不拆。现在已是薄服务端 + 厚客户端，渲染和烘焙都在浏览器里。
