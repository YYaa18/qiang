# 玩法设计

墙现在是一张纸。这份文档讨论的是：在这张纸上还能玩什么。

配套文档：[ARCH.md](ARCH.md) —— 支撑这些玩法所需要的架构与性能改造。

---

## 第零原则：平常的墙才是产品

**一面随便画的纸是默认，玩法是可选的一层。** 不开玩法的墙，行为必须和从来没有过玩法这回事一模一样。

由此推出三条硬规则：

1. **新开的墙没有任何玩法**（`room.mode` 为 `null`，闸门一律放行）。
2. **玩法一结束，痕迹就得清干净。** 揭晓就是接龙的终点——揭晓之后 `room.mode` 立刻摘掉，横幅消失，「接一段」回来，谁都能画。留着一个 `revealed` 的状态挂在那里没有任何用处。
3. **玩法不能留下副作用。** 这条踩过坑：`hidesStrokes` 原本只看玩法有没有定义 `visible`，不看它此刻是否真在藏，于是一个揭晓过的房间**再也不会冻结旧笔画了**。现在揭晓即摘除玩法，副作用随之消失，并有测试守着。

「清空这面墙」也会一并结束正在玩的——清空就是回到一面新的墙。

---

## 第一原则：人数不能成为门槛

墙的真实人数分布不是"4 人"，而是：

> 1 人在线 ≫ 2 人同时在线 > 3–4 人

两人局的凑人成本其实比四人局**更高**。四人局通常是有人张罗的；两人局往往是"我随手画两笔，他晚点来看"。

由此得到一条硬规则：

> **人数只能影响体验的丰富度，不能决定能不能开局。**
> 任何"凑不齐 N 个人就玩不了"的模式，直接砍。

推论：**异步是一等公民，不是降级方案**。墙一直在、人不一定在——这恰好是墙和 skribbl 那类"开局先凑人"的产品的分水岭。做成必须同时在线，就是主动把自己的优势扔掉。

## 按人数重新打分

★★★ 好玩　★★ 能玩　★ 平淡　✗ 玩不了

| 模式 | 2 人 | 3–4 人 | 要同时在线 | 成本 |
|---|---|---|---|---|
| **补全挑战** | ★★★ | ★★ | **否** | 低 |
| **卷轴接龙** | ★★★ | ★★★ | **否** | 低 |
| **我说你画** | ★★★ | ★★ | 是 | 中 |
| **涂地战** | ★★★ | ★★ | 是 | 中 |
| 盲画 | ★★ | ★★★ | 否 | 极低 |
| 限笔共作 | ★★ | ★★ | 否 | 极低 |
| 四格漫画 | ★★ | ★★★ | 否 | 极低 |
| 连线谜题 | ★★ | ★★ | 半 | 中 |
| 你画我猜 | ★ | ★★★ | 是 | 中 |
| 传话筒 | ✗ 链太短 | ★★★ | 是 | 高 |
| 卧底画家 | ✗ | 4 人是下限，5 人才好 | 是 | 高 |

两个需要纠正的判断：

- **卧底画家**不只是"需要 4 人"——4 人是它的**及格线**而不是甜点（一个卧底对三个知情者，推理空间太窄）。它只能是人齐时的彩蛋，不能当主玩法。
- **你画我猜**在 2 人局是平的：一人画一人猜，没有抢答、没有对手，剩下的只是一个人在等另一个人。

## 前两名其实是同一个机制

「补全挑战」和「卷轴接龙」拆开看是一件事：

> **盖住一部分，把笔交出去。**

| 人数 / 时机 | 同一机制的表现 |
|---|---|
| 2 人异步 | 我画一半盖住，你来补完 |
| 2 人同步 | 乒乓式来回接 |
| 3–4 人 | 接力长卷（Exquisite Corpse） |
| 1 人 | 留一段给下一个推门进来的人 |

一套代码覆盖 1–4 人 × 同步/异步四种组合。这是最便宜、也最贴合卷轴形态的起点。

### 机制定义

- 卷轴按**交接点**切段。v1 里一棒 = 一段 1600px，和渲染的分段对齐，最省事。
- 轮到你时，你只能在自己那一段里画；上一段只露出最右边 90px 作为接头。
- 自己画过的段一直看得见——你画的东西没有理由对你保密。
- 遮挡**必须由服务端执行**——不发给你的笔画，客户端就拿不到。藏在前端等于没藏。
- 一段完成（点"交出去"/ 到时 / 笔数用完）后，棒传给下一个人；没有下一个人，棒就放在墙上等人来拿。
- 全部完成后镜头从左到右滚一遍——这是整个玩法的高潮，值得专门做一个"揭晓"动画。

### 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `peek` | 90px | 上一段露出多少 |
| `legW` | 1600 | 每人一段多长（400–3200） |
| `limit` | 无 | 每段限时 / 限笔，可关 |
| `reveal` | 结束时 | 也可以选"永不揭晓"，做成纯装置 |

## 其余模式速记

**我说你画**　一人看题，只能用语言描述（聊天），另一人画。2 人是它的标准形态；4 人时 1 说 3 画，画完并排对比，反而更热闹。信息不对称天然适合两人。

**涂地战**　限时争夺卷轴面积，按颜色统计。墙本来就是四色四人，天生分队制；2 人是最干净的对决。面积统计可以在烘焙时顺便算。

**盲画**　画的时候看不见自己的墨迹，松手才显形。暖场用，几乎零成本（不渲染自己的 live 层即可）。

**限笔共作**　每人一共 N 笔，用完只能看着。逼人下笔前先想。服务端加个计数器就行。

**四格漫画**　把卷轴切成格子，只能画不能说，讲一个故事。两人各两格也成立。

**连线谜题**　各自从卷轴一端连到指定终点，线不能交叉，已画的线是真实障碍物。这是只有共享画布能做的谜题。需要线段相交判定。

**一日一笔 / 风化墙**　每人每天只能画一笔，或者老笔迹逐渐变淡、要有人来"描摹"才能留下。不是游戏，是一个关于什么值得被记住的装置。完全异步，最贴合"1 人在线"的常态。

## 建议的推进顺序

1. ~~**补全挑战 / 卷轴接龙**（同一机制）~~ ✅ **已上线** —— `src/modes/relay.js`

   房主从 ⋯ 菜单「开始接龙」。轮到你时横幅显示「轮到你画这一段」，画完点「交出去」，
   笔就放回墙上等下一个人接；不是你的那几段盖上斜纹，只留上一段最右边 90px 的窄缝用来接线。
   房主「揭晓」后整条卷轴对所有人打开。

   加这个玩法**没有动核心代码**——只新增了 `src/modes/relay.js` 一个文件，
   加上规则层里三样通用的东西（可见性钩子、`{type:"mode"}` 指令通道、藏笔画时不烘焙）。
   下一个玩法应当连那三样也不用再加。
2. ~~**限笔共作**~~ ✅ **已上线** —— `src/modes/limit.js`

   每人只有十笔，用完只能看着。没有轮次，谁都能随时画；约束只有一条：笔数有限。
   撤销会把额度还给你——那是修正，不是作弊。

   **这一步的真正目的是检验抽象，结果是：抽象漏了，补上之后才真正够薄。**

   第一次试的时候，客户端有 44 处写死了「接龙」——横幅上每一句话、每个按钮的文字、
   遮挡的几何，全是 relay 专用的。加第二个玩法根本不可能只写一个文件。

   于是把契约改了：服务端发给客户端的不再是玩法的内部状态，而是一份**显示指令**——

   ```
   label     横幅上那句话
   tone      圆点的样子
   action    横幅上的按钮 {cmd, label}
   blocked   我此刻能不能落笔
   why       画不了时的原因
   drawable  我能画的横向范围，范围外盖上斜纹
   hint      要额外标出来的一小块（接龙的窄缝）
   ```

   外加一份**玩法清单**，⋯ 菜单照着它自己长出来。现在客户端里「relay」这个词一个都不剩，
   它不认识任何具体玩法。

   过程中还发现规则层漏了一件事：每个玩法都得自己拼「发状态给每个人」这段代码，
   relay 就拼漏了 `id` 字段。已收归规则层的 `api.announce()`。

   **最终代价**：`src/modes/limit.js` 一个新文件 + `dispatch.js` 里一行 require。
   服务端其余部分一个字没改。第三个玩法应当就是这个代价了。

3. ~~**盲画**~~ ✅ **已上线** —— `src/modes/blind.js`

   你画的东西只有你自己看不见，别人看得一清二楚（这正是好玩的地方），
   揭晓时你才第一次看见自己干了什么。

   原本设计的是「松手才显形」，实现时改成了「揭晓才显形」——
   松手就看见的话，一笔一笔地纠正，很快就退化成普通画画了；
   一直看不见才逼得你全程凭手感，最后那一下才有落差。

   它的可见性规则和接龙**正好相反**：

   | | 自己画的 | 别人画的 |
   |---|---|---|
   | 接龙 | 看得见 | 看不见 |
   | 盲画 | **看不见** | 看得见 |

   同一个 `visible` 钩子，两条相反的规则——这一层算是立住了。

   「自己看不见」要两边配合：服务端不把你的笔画发回给你（藏在前端等于没藏，
   何况快照也得干净），客户端靠 `hideOwnInk` 不渲染本地那份乐观副本——
   画的时候总得有个本地副本才顺手，所以那一份也得拦住。

   代价：`src/modes/blind.js` 一个新文件 + `dispatch.js` 一行 require +
   客户端两个过滤点（committed 和 live 各一处）。
4. ~~**我说你画**~~ ✅ **已上线** —— `src/modes/tell.js`

   一个人拿到词，只能用话把它描述出来，不能说出那几个字，也不能自己动笔。
   于是只剩下形状、方位、大小：「先画一个大圆，里面点一些小黑点」。
   画的人一路蒙在鼓里，揭晓那一刻才知道自己画的是什么。

   **文档原先说它「需要私密信息分发」——这条预测是错的，那东西早就有了。**
   `publicState(room, user)` 一直是按人调用的，而 `room.mode` 只进磁盘、
   没有任何路径把它整个发给客户端。所以词只出现在拿词那个人的那一支返回里，
   一行新机制都不用加。

   同样，「不许说出那个词」也不需要新东西——闸门本来就收 `chat` 动作和消息内容。
   禁的是词本身和它两个字以上的片段（「长颈鹿」连「长颈」「颈鹿」一起禁），
   单个字不禁，否则「大」「人」这种常用字一禁就没法说话了。

   拿词的人和接龙的笔一样是一根接力棒：可以没人拿着，谁来谁接；
   中途走了词就放回墙上，两人局掉一个人也不卡死。接手的人会拿到一个**新词**，
   因为上一个人已经看过了。

   代价：`src/modes/tell.js` 一个新文件 + `dispatch.js` 一行 require。
   **客户端一个字没改。**
5. ~~**涂地战**~~ ✅ **已上线** —— `src/modes/turf.js`

   限时抢地盘，涂在别人上面就抢过来，橡皮能擦回无主。到点自动结算报名次。

   **这次「需要新东西」的预测是对的**，但难点不在统计面积，在于**重叠**：
   按笔画长度乘粗细去累加的话，在同一块地方来回涂分数会一直涨，
   这一条就足以毁掉整个玩法。

   所以不算面积，改成**把墙切成 20px 的格子，每一格归最后涂它的那个人**。
   涂在别人上面就抢过来，橡皮擦回无主。纯整数运算——不需要画布、不需要新依赖，
   也不必信任客户端报上来的数（如果让客户端算，就和烘焙一样得信它）。

   格子只活在内存里（放在 `WeakMap` 里，不会被写进存盘文件）。
   撤销/重做会打乱谁压在谁上面，那时整块重算最省心。

   它也是**第一个真正用上「定时器只存 deadline」那条规矩**的玩法：
   `endsAt` 跟着房间存盘，`restore` 重新挂上倒计时，重启后接着倒。
   客户端拿到 `endsAt` 自己倒数，服务端不每秒广播（那条规矩当初就是为这写的）。

   代价：`src/modes/turf.js` 一个新文件 + `dispatch.js` 一行 require +
   客户端一处通用改动（横幅显示倒计时，任何限时玩法都用得上）。
6. ~~**一日一笔**~~ ✅ **已上线** —— `src/modes/daily.js`

   每人每天只能画一笔，零点换日。这是第一个专为「1 人在线」这种常态做的玩法：
   不需要任何人同时在，今天推门进来，看看别人昨天留下的那一笔，想好了再落自己的。

   让「一笔」真的只有一笔，靠的是撤销规则：

   | | 今天画的 | 昨天以前画的 |
   |---|---|---|
   | 撤销 | 可以，额度还你 | **不行**——它已经是墙的一部分 |
   | 重做 | 只在今天还有额度时 | —— |

   橡皮和文字也算一笔。「今天」按 `QIANG_TZ`（默认 `Asia/Shanghai`）算，
   而不是服务器本机时区——VPS 常在 UTC，零点不该落在早上八点。

   零点那一刻要告诉在场的人「又能画了」，所以挂一个到下一个零点的定时器，
   和涂地战一样只在内存里、由 `restore` 重挂；房间被请出内存后旧定时器会自己作废。
   横幅没有复用 `endsAt` 倒计时——离零点还有十几个小时，`734:12` 这种钟没法看。

   原本设想的「风化墙」（老笔迹变淡）没一起做：冻结后的笔画已经烘焙成整段墨迹图，
   没有单笔的年龄可用，得另想按段淡化的办法。

   代价：`src/modes/daily.js` 一个新文件 + `dispatch.js` 一行 require。
   **客户端一个字没改。**
**揭晓走一遍展厅**　接龙、盲画、我说你画揭晓时，每个人的屏幕自动打开 3D 展厅，
从头走一遍整条卷轴——文档一开始就说「揭晓值得专门做一个动画」，这就是那个动画。

三个玩法揭晓时本来就会 `presence.resend(room)` 给每人重发整墙，
现在多带一个 `{ reveal: "接龙" }` 并进那份快照。客户端换上快照之后再开展厅，
展厅里才是揭晓后的整墙，而不是揭晓前被遮住的样子。
记号只挂在那一次重发上，揭晓之后才进门的人拿到的是普通快照，不会被突然拉进展厅。

7. ~~**连线谜题**~~ ✅ **已上线** —— `src/modes/link.js`

   墙上接出一段干净的纸（最后一段本来就空着就直接用），撒几对彩色圆点，
   把同色的连起来，线不能交叉、不能压到别的点。谁都能连任何一对，一个人也解得完，
   线留在墙上就是后来者的障碍——这是只有共享画布才做得出的谜题。

   在没有边的纸上这种题永远有解，线总能绕过去；难的是次序。出题时专挑
   「两两直连会交叉」的摆法，不然就是连连看。

   **交叉判定用几何，不用涂地战的格子。** 格子是按采样点落格的，两条线恰好
   擦过同一格的对角时会漏判；这里要的是「穿没穿过」的硬答案。
   几千个点的长线两两比太慢，先把已有线段按 60px 分桶，新线每一小段只比它经过的桶。

   这次规则层真的缺了两样东西，都加在 `wall/draw.js` 里，以后的玩法也用得上：

   - `placeStroke`：玩法自己往墙上放一笔。圆点就是真的墨迹，不进任何人的撤销栈，
     之后和别的笔一样冻结、导出、进展厅。
   - `retractStroke`：把刚落定的一笔退回去。对屋里的人来说就是一次撤销——
     客户端本来就认 `undo`，所以不用新消息；但不进重做栈，退回的笔不该被重做回来。

   `presence.growWall` 是从「接一段」里拆出来的，玩法要一段新纸时用。

   已连上的线把自己的点存在 `room.mode` 里，而不是回 `room.strokes` 去找——
   墙上的笔一多就会冻结成墨迹图，那时候就找不到它了。

   **做这个玩法时顺带修掉了两个老 bug**，都是之前的玩法碰巧没踩到：

   - 房主「结束」玩法时服务端不通知任何人，横幅和斜纹一直挂到刷新。
     接龙、盲画、我说你画、涂地战的收尾自己会重发，所以没暴露；限笔和一日一笔都中招。
     现在规则层在 stop 之后统一 announce，不再指望每个玩法记得。
   - 客户端 `lookAtDrawable`（「把镜头带到我能画的那一段」）平移算反了符号，
     只要能画的不是第一段，镜头就被夹回最左边。接龙从第二棒起就一直是坏的。
     另外能画的范围比屏幕宽时现在会缩小到装得下——谜题得一眼看全所有点。

   代价：`link.js` 一个新文件 + `dispatch.js` 一行 require +
   `draw.js` / `presence.js` 里三个通用函数。客户端只有那个 bug 修复。
8. 卧底画家、传话筒——等哪天真有四五个人在墙上再说。
